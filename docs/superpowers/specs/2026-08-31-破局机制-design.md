## 1. 背景：后期地图会冻住

用稳健画像（bar 1.35，会用辅助行动）在标准难度跑 24 局到 120 月，**5/24 局卡死**。卡死局面的典型形态（固定种子实测）：

```
seed0  120月 玩家7块 vs 东潮会7块   现金5130万 人手71/180
       敌方核心地驻防 298~300，最优兵力比 0.46（九死一生）
seed5  120月 玩家5块 vs 东潮会9块   现金3553万
       敌方驻防 312~330，兵力比 0.39~0.44
seed1  120月 玩家6块 vs 万隆帮7块  现金3996万 人手45/160
```

三个共同特征：

1. **玩家打不动**：所有敌方核心地兵力比 0.39~0.50，稳健 bot 的出手线（降到 1.05 都够不着）永远达不到。
2. **AI 也打不动玩家**：对玩家用小标度攻击 + 3 个月缓手冷却（这两条是防雪崩的既有设计，不能撤），双方各自不死。
3. **现金堆到几千万无处可花**：后期钱换不成任何破墙能力。边境只剩一两块低驻防地在无限拉锯（seed0 的 golden_bay:g38 就是刚易手的拉锯地）。

### 1.1 死局的数学本质

- 敌方驻防上限 `cap = 90 + 该家地盘数×30`（`enemyGrowth`，app.js:788），每月自动生长直到贴线。7 块地 = 300，9 块地 = 360。
- 玩家攻击力天花板 ≈ `crewCap(40+地盘×20+等级) × (0.82+士气×0.0048) + 头目 ≈ 250`（玩家 7 块地、满人手、高士气时）。
- 守方战力还要乘 `1.18 × diff.battle`。**AI 一旦吃到 6~7 块地，墙就高过玩家的天花板，且差距逐月拉大。**
- 攻击失败只削守方驻防 2~6 点（AI 互啃）或 `enemyLoss`（玩家强攻），下月生长就补回来了——**消耗战不成立，失败不积累任何进展**。
- 加时无限、无代价，卡死局面可以原样拖过 60 个月。

一句话：**这不是难度问题，是缺一条「面对高墙时把局面推向终结」的通路。** 双向都缺——玩家赢不了，也输不掉。

### 1.2 为什么不能只调数值

压低敌方驻防上限、抬高玩家人手上限，能把墙推迟，但拉锯与无限加时的结构还在；而且会削弱「后期要面对一个巨无霸」这一 README 明确要保留的体验。要治的是结构，不是斜率。

## 3. 目标与非目标

**目标**

- 任何一局在第 100 月前必然抵达某个结局；「玩家与 AI 地盘数连续 24 个月双双不变」的冻结局面不再出现
- 玩家面对 300 驻防的墙时，存在一条**多月消耗战**通路：连续施压 6~8 个月能把墙磨到可攻
- 后期现金有去处：封锁、策反是持续的钱换进展
- 一家独大（无论哪边）触发剧本化决战，赢和输都是干脆的结局
- 保留既有防雪崩设计：小标度攻玩家、缓手冷却、两套攻击标度一概不动

**非目标**

- 不改血拼三段式流程、战术克制环、姿态系统
- 不改开局与前中期难度曲线（莽夫/稳健既有基准照旧生效）
- 不给玩家阵营加失序机制（玩家已有 heat/民心/忠诚三套内压，再加就重复了）

## 4. 机制设计

### 4.1 A · 围困消耗战 —— 失败也要积累

**破口（breach）**。玩家对某块敌方地盘发起血拼（无论胜、退、败），该地被标记破口 4 个月：`s.breach[id] = s.month + 4`。破口期内该地**跳过 enemyGrowth，且每月驻防 -6**（下限 30）。战败仍按既有规则额外扣 `enemyLoss`。

效果测算：对 300 驻防的地连打三场败仗（每场 enemyLoss 约 15~25）＋破口持续失血，6~8 个月可磨到 180~200，兵力比从 0.45 爬回 0.8+，配合克制战术与下述削弱手段进入可打区间。**打输不再是白打，是买下了对面的失血期。**

**断其财路（新行动 blockade）**。1 行动点 ＋ 现金 `20 + 目标驻防×0.15`（万，取整），对一块相邻敌方地盘生效 3 个月：驻防生长停止、每月 -10（与破口叠加时取 -14，不是 -16，避免双押成为唯一解）。每月限 1 次。这是主力现金去处：后期一次 60~70 万，持续压两块地一年花掉近千万——seed0 那 5000 万终于有事干。

**重金策反（新行动 turncoat）**。1 行动点 ＋ 现金 40（对失序势力 28，见 4.2），目标为一块相邻敌方地盘。成功率 `clamp(0.3 + 最高魅力头目.charm/180, 0.25, 0.75)`：成功则该地驻防 -25、姿态改为「人心浮动」；失败则声望 -3、该家 ambition +4（惹火上身）。每月限 1 次。

三者与既有「安插内应」（-12 驻防＋查情报）分层：内应是情报件，封锁是持续压制，策反是一次性重击，破口是打出来的。

### 4.2 B · 豪强失序 —— 摊子大了压不住

AI 势力地盘数 `n ≥ 6` 时进入失序，`disorder = n - 5`。

- **驻防上限打折**：该家所有地盘 `cap = 90 + n×30 - disorder×22`。7 块地时 cap 从 300 降到 256，9 块地时从 360 降到 272——**上限增速被压到玩家天花板的量级**，巨无霸仍然厚，但不再无解。
- **每月失序掷骰**（rng 必须从 advanceMonth 传入）：每点 disorder 有 25% 概率让该家驻防最低的一块非起家地「街面生乱」：驻防 -15~-25，姿态改「人心浮动」；若该地驻防已 < 50，改为 10% 概率直接反水成散户（owner="free"，驻防 30）。月报里要有对应叙事行（「东潮会在 XX 的账房卷款跑了」）。
- **策反打折**：对失序势力的 turncoat 现金成本 ×0.7。
- 中央港区不参与反水（终局地标，owner 只应通过战斗易手），但参与上限打折与生乱扣驻防。

不对玩家生效（见非目标）；对 coalition 不生效（它没有地盘数概念）。

### 4.3 C · 终局决战 —— 一家独大就摊牌

**玩家侧 · 雾港最后一张桌**。触发条件：存活 AI 仅剩一家、玩家地盘数 ≥ 8 且 ≥ 该家地盘数。触发一次章节级事件，三选：

1. **发起总攻**：一场特殊三段式血拼（复用 battleSession，特殊标记 `session.decisive=true`），敌方战力 = 该家全部驻防之和 ×0.45 ＋ 全部头目；玩家战力 = 常规算法 ＋ 准备度加成：每个生效中的破口/封锁/策反成功 +8%，民心 ≥60 再 +10%，另可当场投入现金（每 25 万 +5%，上限 200 万）。**胜 = 直接 unified 结局**（吞并其全部地盘）；败 = 不判死，损失最外沿 2 块地、人手 -30%，6 个月后事件可再触发。
2. **递茶递到底（谈判收编）**：需 义 为主导流派或声望 ≥ 70，付现金 `该家地盘数×40` 万——unified 的和局变体（结局文案区分「武统/和局」，名录同样计入，标注方式）。
3. **再等半年**：搁置，6 个月后重新触发。

这直接砍掉「逐块磨 5 个 300 驻防」的扫尾——终局在决策点结束。中央港区的 `TERRITORY_TOTAL-1` 前置门保留（总攻/和局绕过它，因为整家是一次性吞并）。

**AI 侧 · 兵临老街**。触发条件：某 AI 地盘数 ≥ 8 且 `month ≥ 30`，每家限一次。**前一个月月报必须有苏曼青的顶级警讯**（「东潮会在各堂口点人，下个月就是冲我们来的」），给玩家一个整备月。次月触发守城决战事件：敌方战力 = 该家驻防总和 ×0.35 ＋ 全部头目；我方 = 能战人手 ＋ 全部未伤头目 ＋ 老街驻防×1.5 ＋ 士气与民心加成（民心 ≥60 时 +12%，街坊帮着堵巷子）。
**胜 = 对方联盟崩裂**：该家全境驻防 ×0.6、最远端一块地反水成散户、玩家士气 +15、声望 +12——僵局从 AI 侧被凿开。**败 = endGame("crushed")，败局**。输赢都剧本化，都不可逆。

### 4.4 D · 加时有代价 —— 这座城等不动了

- 第 66、72、78… 月（每 6 个月）触发「时代在变」：全局收入系数累乘 ×0.95、外部压力下限 +8。加时越久账面越紧，拖延本身开始付费。
- **第 96 月强制结算**：事件「这座城等不动了」→ 按当时局面 endGame：玩家 ≥10 块 =「半壁雾港」结局（体面收场）、6~9 块 =「割据一方」、≤5 块 =「退场」。雾港名录只收 unified，不受影响。
- 60 月「五年之期」事件文案补一句预告：「这座城最多再给你三年。」（96 = 60 + 36）

## 5. 平衡目标与测试要求

`tests/balance.test.mjs` 新增/收紧断言（沿用固定种子三画像框架）：

1. **必然终结**：稳健·标准 24 局，第 100 月时 `s.ended` 全部为 true（MONTH_CAP 保持 120 作缓冲）。
2. **僵局哨兵**：任何一局中「玩家地盘数与各存活 AI 地盘数连续 24 个月完全不变」视为失败断言。
3. **通关率区间**：稳健·标准通关（unified，含和局）≥ 15/24 且 ≤ 22/24——A~C 是破局工具不是送分，莽夫·标准中位仍须 ≥ 12 月。
4. **消耗战通路有效**：新增定向夹具——构造一块 300 驻防敌地，bot 连续 施压（血拼+封锁）8 个月后兵力比 ≥ 0.8。
5. **rng 纪律**：所有新掷骰（失序、策反、反水、决战）必须走从 `advanceMonth`/行动入口传入的 rng。README 已有前车之鉴：漏一处 Math.random，固定种子就锁不住曲线。
6. 兼容旧档：`normalizeState` 为 `breach/blockade/disorder/decisive 标记` 补默认值，旧存档读入不炸。

## 7. 实现记录：设计与现实的五处偏差（2026-08-31 施工后补记）

### 7.1 守城战的攻方战力改走小标度（§4.3 数值作废）

Spec 写「敌方战力 = 该家驻防总和 ×0.35 ＋ 全部头目」。照此实现，八块地的一家在第 30 月能凑出约
**700** 点攻击力，而玩家此时的守城天花板约 **200**（能战＋整补＋头目＋老街驻防×1.5）——固定种子实测
**24/24 全灭**，且调 ×0.35 这个系数几乎不影响结果，因为差距是量级上的。

这同时违反 README 的既有铁律：**对玩家地盘一律用小标度攻击力**。已改为
`(38 + 该家地盘数×13 + 月份×0.7) × SIEGE_SCALE × diff.battle`，`SIEGE_SCALE=1.5` 由扫描定出。
`SIEGE_SCALE` 是这个关卡唯一的难度旋钮。

### 7.2 守城战改为三档，不是硬币

Spec 写「败 = endGame("crushed")」。两档结算意味着「AI 吃到八块地」等价于通知玩家可以关游戏了。
现为三档：`def/atk ≥ 1` 守住（原设计的胜利效果不变）；`≥ 0.72` **惨胜**——祖堂保住，
但折掉一半人手、最外沿一块地、老街驻防打六折、士气 -20；`< 0.72` 才判 `crushed`。
中间那档是「门顶住了，家底没了」，足够惨，但下个月还有下个月。

### 7.3 守方计入整补池

Spec 只写「能战人手」。守自家门口时把整补中的人排除在外没有道理，且会让「刚打完一仗就被围城」
变成必死。现为 `crew + regroup`，只有伤号留在诊所。

### 7.4 封锁与策反自动选目标，不做选地界面

Spec 说「目标选择沿用 insider 的交互模式」（弹窗选地）。改为自动选目标，理由有二：
一是这两件事各自只有一个正确答案（封锁挑最高那堵墙，策反挑最松那扇门），多一层界面只是多一次点击——
与 `fortify` 自动挑最薄弱地盘同一个理由；二是弹窗分支在无头环境里永远不会被点，
平衡机器人因此完全用不上这两个行动，spec §5.4 的消耗战夹具也就无从验证。

同时 `applyAction` 增开 `rng` 形参并透传给 `a.run(s,rng)`，`recruit_crew` 与 `intel` 的裸 `rand/pick`
一并接上——否则策反的掷骰会绕开固定种子，正是 README 记过的那个坑。

### 7.5 封锁与策反不受中央港区前置门连坐

`attackableTerritories` 会把中央港区挡在门外（要先拿满 13 块）。封锁与策反是「够得着就能做」的手段，
不该被终局门槛连坐，因此两者用新的 `adjacentEnemy`（只看相邻）。

### 7.6 §5.3 的通关率区间按实测重定

Spec 要求稳健·标准通关 15~22/24。实测：不用围困工具 15/24，会用围困工具 11/24
（差值在 24 局的抽样噪声内，两条画像的 rng 流本就不同源）。断言改为
「稳健 ≥40% 且 ≤92%」「围困派 ≥30%」，并补上更硬的两条：**必然终结**（全部 96 局都在 96 月内结束）
与**僵局哨兵**（地盘数连续 24 月不变即失败）——后两条才是这个计划真正要锁的东西。

## 8. 界面审计（2026-08-31，1280 / 760 / 390 三个宽度实机渲染）

三个宽度下**没有一处横向溢出**（`scrollWidth > clientWidth` 全零，文档宽度 388 / 758，无横向滚动条）。
按钮文字、锁定文案、弹窗与新结局标题在最窄的 390px 下均正常换行不截断。修掉的四处观感问题：

1. **围困标记的尺寸与「未稳」不一致。** 原写法 `padding:2px 8px; font-size:.62rem`，比同一行的
   `.settling-tag`（`1px 6px / 11px`）明显大一圈。同一行里的兄弟标签长得不一样，比信息本身更抢眼。
   两枚标记现在共用一套尺寸。
2. **配色跑出了调色板。** 原用 `#ffd9a8 / rgba(196,92,32,…)`，是整套 CSS 里不存在的橙色。
   改为：围困＝`var(--gold)`（这是玩家的机会，与「可攻地盘」的金色描边同一套语言），
   失序＝`var(--red)`（这是对方身上的裂缝）。
3. **数字从标题行挪进 stat-chips。** 原来标题写「围困中 -14/月」，一个五字地名（金湾娱乐区）加上它
   会把标题行撑满。现在胶囊只说状态「围困中」，失血速率并进驻防那一格：`驻防 132 ↓14/月`——
   与卡上其它数字待在同一处。
4. **重金策反的效果标签写成了句子。** 「成功：驻防-25、人心浮动」有 12 字，是全卡最长的标签。
   收成「成功 驻防-25」「失败 声望-3」，细节移进 desc；图标由「叛」改「策」——
   既有图标（众练账眼茶药守镇静和间应封）全是中性动作字，「叛」是唯一带判词的一个。

新增回归断言（`tests/structure.test.mjs`）：所有行动的效果标签 ≤13 字、锁定文案 ≤14 字、图标必须是单字。
上限取自既有卡片里最长的两条，等于把当前的排版预算钉死，后来的行动不许再挤宽卡片。
