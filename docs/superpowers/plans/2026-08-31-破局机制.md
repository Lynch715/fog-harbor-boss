# 破局机制：围困消耗战、豪强失序、终局决战、加时结算

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消灭后期死局。当前标准难度稳健画像 5/24 局在 120 月仍未终结（敌方驻防 300+ vs 玩家攻击天花板 ~250，双方互相打不动）。四组机制让每局必然在 100 月前抵达结局。

**Spec:** `docs/superpowers/specs/2026-08-31-破局机制-design.md`（数值与触发条件以 spec 为准，本文只列施工顺序与验收）

**Tech Stack:** 原生 JavaScript 单文件 `app.js`（紧凑单行风格），`node:assert/strict` 测试，无构建步骤。

---

## 铁律（违者返工）

1. **rng 一路传到底。** 失序掷骰、策反判定、反水、决战伤亡——所有新随机必须接收从 `advanceMonth` 或行动入口传入的 rng 参数，禁止裸 `Math.random`。历史教训见 README：漏一处，balance 测试的固定种子就废了。
2. **不动防雪崩三件套**：小标度攻玩家、`aiPityUntil` 缓手冷却、两套攻击标度。
3. **旧档兼容**：所有新状态字段在 `normalizeState` 补默认值（`s.breach={}`、`s.blockade={}`、`s.factions[f].disorder=0`、`s.flags.decisiveOffered`、`s.flags.siegeWarned` 等），载入旧存档不得报错。
4. **风格**：紧凑单行函数体，注释解释「为什么」；新行动直接加进 `ACTIONS` 数组（UI 自动渲染，先确认 renderer 对新增项无硬编码依赖）。
5. 每个 Part 结束跑：`node --check app.js && node tests/structure.test.mjs && node tests/balance.test.mjs`，全绿才进下一个 Part。最终跑 `python3 build_single.py`。

### Part 2 · 豪强失序（spec §4.2）

**Task 4: disorder 与上限打折**
